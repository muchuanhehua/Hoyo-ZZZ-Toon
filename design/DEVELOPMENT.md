## 0.1.2：City-Terrace 共用基础修正

用户指定的 `../City-Terrace/city-terrace-environment.blend` 作为只读背景。场景检查为 321 个对象，原相机为 50.424 mm 透视，Standard／None／曝光 0／Gamma 1；原暖色主光能量 2.2，蓝色补光 0.75 与 0.38。使用原相机做全身对照，所有模型用同一规则贴合原点地面，不按角色改尺寸、光照、材质或色彩管理。

本轮证据目录为 `.verification/terrace-views-20261031/`。共用头部视角为正面、左右 90°、侧后 135°、背面 180°，另在正面关闭补光、主光旋转 180° 做背光压力检查。画面外遮挡物与可见脸部遮罩用于验证真实阴影响应，不让遮挡物本身进入相机。

已经确认并实现：

- 原脸影没有读取实际遮挡。哲、青衣、爱丽丝、照的旧链路遮挡前后脸部平均暗化接近 0；候选为约 0.088–0.102，源 Alpha 不变。当前使用 0.65 法线／0.35 头部前向的统一体积近似，并由真实 Diffuse 光照限制亮面，仍无角色 SDF。
- 94 个头发材质的实际纹理索引审计中，23 项、13 个主体具有透明区域。审计按官方 PMX 解析结果读取实际路径；初次仅用盘点显示文件名拼接的无效路径扫描已明确作废，不作为缺图结论。
- 整体切换 Dithered 会破坏共面贴花。诺姆的 7,271 个高光三角面与前面头发重合，波可娜的毛片也与衣装重合。独立发面采用深度覆盖；按实际源几何和材质槽顺序识别后绘制的透明重合层，保留混合叠加。坐标精度约为模型高度的百万分之一，不移动、删除或合并源面。
- 仅双向标记重合也不正确：主头发与后面的 `髮+` 高光重合时，应保留主层的深度覆盖。当前判定使用源顺序，仅标记后绘制层。`candidate-smoke/` 的这一中间结果保留，不作为最终通过证据。

最小平面、同网格分层、共面层、隔离高光层，以及关闭描边／阴影、硬裁切、单 UV、纯纹理等探针均保留；未采用无效方案，未删除源 UV 或关闭正式描边来掩盖问题。0.1.1 的 10 个模型统一视角从四组原始探针汇总到 `baseline/`，各组运行源码摘要一致，来源路径写入汇总。

0.1.2 的 `verified/` 完成 10 个模型、每个模型全身＋六个头部视角，以及遮挡物控制检查，运行失败 0。脸部平均暗化范围为 0.0845–0.1351（归一化 RGB 平均差）；所有案例的源文件、环境文件与原数据保持，恢复通过。`review/` 的 10 份修正前后图均已查看；概览为 `review/overview.png`。

本轮生命周期证据 `regression/verification.json` 为通过：新源码的注册／重注册、真实参数与光照响应、重复应用资源及像素稳定、注入失败回滚、恢复和保存重开通过。全部主体的新回归 `all-models/report.json` 已完成：49 个主体全部尝试，46 出图／3 启用贴图缺失中断／0 运行失败；49 个案例的源文件及原数据保持，46 个出图案例恢复通过。`all-models-review/` 的 12 页均已查看。

## Face SDF 接入研究（2026-10-31）

结论：可以沿用当前头部控制器和独立资源生命周期，增加共用 Face SDF 核心。已有原始脸影图可作为输入，无须先为每个角色制作 SDF 或配置参数。是否能使用某张图，仍取决于该模型的脸部 UV 和资源对应关系；不能把 PMX Toon／Sphere 或任意灰度图当作 SDF。

用户进一步明确：同名 Lightmap 应按共享资产理解，角色文件夹中的图像是资产副本。接入设计据此采用共享资产目录，角色仅引用资产及 UV；本轮按像素分组的结果只描述内容差异，不作为角色专属资产或单角色配置的依据。

前置研究批次新增四个研究工具并补充本开发记录：`tools/research_face_sdf.py`、`tools/research_sdf_resources.py`、`tools/research_sdf_uv.py`、`tools/probe_sdf_sampling.py`。私人输入、提取图像、UV 数据和探针输出均位于忽略的 `.verification/sdf-research-20261031/`，不进入候选包。原模型、参考工程和当前前台工程没有修改。

### 已核对的参考链路

- 本地两份 Kythera V2 中，Face 顶层材质、主组和递归子组的本轮序列化结果一致，包含连接、可读取的输入默认值、Math／Mix 参数、Ramp、Float Curve 点及抽样值。这不是全部 Body／Eye 参数或两版渲染等价性验证。
- V2 的 `Face Lightmap` 是 Closure 输入。外部图像节点接收核心给出的 `Vector`，返回 Color 和 Alpha；核心使用 **R 与 Alpha**，本轮未发现 G／B 接入这段脸影边界链路。Closure 是外部采样接口，本身不是另一种 SDF 资源。
- 艾莲、青衣、薇薇安的现有角色工程采用 V1.5，Lightmap 放在内嵌三节点组中；同一张图在艾莲／薇薇安工程标为 sRGB、在青衣标为 Non-Color，不能继承这种不一致的图像设置，也不能将这些工程称作 V2 渲染结果。
- 本地 1.7.1 的 `_kysh_apply_lightmap` 查找主 Face 组内“直接含 Image Texture 的子组”。V2 的两个直接子组 `Lit/Shadow`、`Rim Light` 均没有图像节点，因此该查找路径无法替换 V2 外部 Closure 的 Lightmap。Hoyo 应自行管理采样器，不直接复制这段换图流程。
- 原版头部 Empty 的 +X 是人物左方，+Y 是脑后；当前 Hoyo 的 `HZZ_RIGHT`、`HZZ_FRONT` 是人物右方、面前。接入原版数学时必须分别取负，不能只替换属性名。

本轮还核对了 [Blender 官方 5.0 渲染说明](https://developer.blender.org/docs/release_notes/5.0/rendering/)：Shader 支持传入并求值 Closure。接口设计以当前实际检查的 Blender 5.2.3 LTS 为目标，不据此宣称旧 Blender 版本兼容。

### 核心数学与数据语义

以下为本地 V2 脸影子链路的转写，不是当前 Hoyo 的实现。令 `F` 为 Hoyo 面前方向、`R` 为人物右向、`L` 为朝向主 Sun 的单位向量，`C` 为原版 Float Curve：

```text
front_dot = dot(-F, L)
sample_u = u if dot(L, -R) > 0 else -u
sample = FaceLightmap(sample_u, v)  # Linear + Repeat
q = clamp(2 * sample.R - C(front_dot), 0, 1) * sample.Alpha
sdf_lit = remap_clamped(q, 0.35, 0.40, 0, 1)
        * remap_clamped(q, 0.35, 1.00, 0.75, 1)
```

`-u` 在 Repeat 下与 `1-u` 周期等价，但生产实现应保留明确的采样方式并检查接缝。原版使用三维点积和曲线，并未在此链路先投影到水平面、归一化后计算方位角；首轮复现不另换一种角度模型。原曲线点约为 `(0,0)`、`(0.25,0.5)`、`(0.346591,0.512501)`、`(1,2)`，负区间外推；点、手柄类型和求值样本已记录，不能用任意线性阈值替代。

Lightmap 的 Alpha 是参与 `q` 的数据遮罩，**不是生成材质的最终透明度**；PMX 原贴图 Alpha 和材质 Alpha 仍走原有覆盖率链路。V2 后续还把上述结果与 Lit Intensity、Generated 空间遮罩和 `Diffuse BSDF → Shader to RGB` 的 Ramp 相乘，再混合明暗颜色。该 Diffuse 结果包含真实受光和遮挡，并非单独的 shadow-only 因子。

因此，接入时不能继续把 `sdf_lit` 交给当前基础脸影的 `MINIMUM(方向法线明暗, 原生受光)` 并再次应用基础 Toon 阈值。需要让已形成明暗遮罩的 SDF 路径直接参与颜色混合，单独验证实际受光／遮挡的组合规则；首轮先对照原版，不声称已经分离出纯遮挡。

当前 `materials/basic.py:ImageCache.load` 统一创建 sRGB 图像，缓存键也没有数据用途。增强接入需要独立 `Non-Color` 图像副本，缓存键包含数据用途、色彩空间及 Alpha 语义，保持源图像独立。可采用明确表示独立数据通道的 `CHANNEL_PACKED`，但仍需在实际角色和线性采样边缘与原版比对。[Blender 官方 Image API](https://docs.blender.org/api/5.0/bpy.types.Image.html) 明确区分 Channel Packed 与关联透明度的含义。

隔离 EEVEE 探针已检查一个分数 Alpha 像素的六种组合：Non-Color 下 PREMUL／STRAIGHT／CHANNEL_PACKED 在此像素输出一致，R 约 0.9761、A 约 0.5957；sRGB + PREMUL 的 R 约 0.5176。Non-Color + Channel Packed 与源像素的最大差约 0.000397，符合探针的 0.002 核对界限。这只证明该常量 UV／Closest 采样点，未验证整图或 Linear 边缘等价。首次未显式连接 Vector 的无效探针已单列，不能作为通过证据。

## 共享 Face SDF 原型（2026-10-31）

结论：三份 PMX 可以在原有 UV 上使用同一基础 Female Lightmap，复用一套 SDF 数学和参数进行静态渲染。当前视角中，基础脸影在鼻部／颊部的碎块状边界有所减少，固定主光下转动实际头骨时明暗边界随之变化；这属于本轮画面观察，不是游戏截图的还原度验收。

### 共享输入和材质接法

- 三个独立进程均引用相同文件内容：逻辑资产 `Female_Face_Lightmap.png`，文件 SHA256 为 `e1a36b7662a8271273e95fc1eeb0779376280ea39dd35f3880433fac3eba46e3`，256×256，Non-Color／Channel Packed，Linear／Repeat。来源是已经核对过的共享资产副本；不按角色重新选图或调参数。

### 原版控制与投影接收修正

`kernel-control-v3/kernel-validation.json` 检查了前方、左右侧和后方四个方向；每向以原型和原版并排采样同一共享图，排除光栅边框后的 252×252 控制区域最大／平均差均为 0。这里仅核对 authored SDF 遮罩，不包括原版调色、Rim、SSS 或真实受光组合。

早期 `renders-v1/` 的空间加权方案和 `renders-v2/` 的固定受光 Ramp 方案均在艾莲投影检查中失败，未继续作为通过结果。后续同条件对照确认遮挡物有效：基础脸影平均变暗约 0.0949，旧原型为 0。HDR 探针测到被遮挡脸部仍有约 `[0.254, 0.443, 0.523]` 的环境受光；参考的 0.1–0.2 Ramp 将其截成满亮，导致投影变化被丢掉。相关证据保留于 `receiver-probe/`，不能把失败归为模型缺图或单角色适配问题。

最终 v3 原型用统一的 Sun-facing Diffuse 接收器取原生受光，再以 `clamp(luminance(received_light), 0, 1)` 参与组合：

```text
face_lit = authored_sdf_lit * clamp(luminance(Diffuse(normal=HZZ_SUN)), 0, 1)
face_color = original_pmx_color * mix(shared_shadow_color, white, face_lit)
```

这保留 EEVEE 的实际投影与环境受光，并避免在 SDF 上再次叠加脸部几何法线的 Lambert 边界。它仍是受光强度信号，不是隔离的 shadow-only 通道；多灯与环境光很强时的行为需要扩大验证。最终原型没有采用早期空间豁免，也不再保留早期接收坐标属性。

### 参考与问题定位

- 固定本地 Kythera V2（SHA256 `0ca2238ec9b68a00c6d270666829827f839a770df8fd4b66e1c3af99d83a4c52`）读取主身体组与 `Lit/Shadow`、Rim 子组。亮暗颜色分别计算，暗色经过 HSV 饱和度／明度曲线后乘 Shadow Tint，再按受光混合。`tools/inspect_body_reference.py` 及私有 `reference/body.json` 保存实际节点与连接，不把参考工程打包。
- 查阅 VRM Consortium 的 MToon 1.0 规范、Santarh 的 MToon 源码和 Blender 5.2 EEVEE 节点支持说明。采用光向分区、亮暗颜色和受光颜色分开处理的思想，使用本项目的原生节点构建器；链接见 `docs/upstream-baseline.md`。
- 原身体链路先将实际受光 RGB 转灰度，再以阈值分区，并将自定义阴影与 PMX Toon 相乘。World／补光较强时容易压平主光方向层次。艾莲、青衣、薇薇安的多数源 PMX 材质 Specular 为零或接近零，不能把全身色差归因于额外金属高光。
- 原始游戏 `_M`／`_A` 区域图没有对这些 PMX 普遍确认，未借文件名自动套用。PMX Toon／Sphere 保留原语义，不替代游戏 Lightmap 或金属／粗糙度图。

### 实现与默认参数

`materials/basic.py` 负责装配基础色、脸影／主体着色、响应和覆盖。`materials/images.py` 管理图像语义与 Alpha 缓存；`materials/lighting.py` 管理主光分区、原生受光与共享亮暗配色；`materials/responses.py` 独立保存原有 PMX Specular／shininess 与 Sphere 响应。

身体／头发使用：

```text
base = PMX_Base × PMX_Diffuse × tint
key = smoothstep(position + hairShift ± softness, dot(N, Sun))
received = ShaderToRGB(Diffuse(white, normal=Sun))
lit = key × clamp(luminance(received), 0, 1)
shade = HSVShadowCurves(base) × bodyShadowTint
stylized = mix(shade, base, lit)
if PMX_Toon: stylized = mix(stylized, base × PMX_Toon(lit), toonStrength)
color = stylized × mix(white, received / max(luminance(received), .001), lightColorStrength)
```

随后组合 PMX Specular 与 Sphere，最终沿原 Alpha／覆盖规则输出。主光分区不依赖 World 强度；原生接收器仍包含场景的主光、补光与环境照明，不能将它称为单独的可见度／阴影贴图。环境光会填亮实际阴影。

新增共用默认值：主体暗部色调 `(.73790556, .81484711, 1)`、灯光颜色影响 `.65`、PMX 色带混合 `.25`、头发明暗偏移 `.08`。原阴影位置 `.42`、过渡 `.025`、额外高光 `0` 保留；脸部阴影颜色仍为 `(.62, .68, .82)`。默认 BASIC 与显式共享 SDF 的选择规则保留，不给其他资产默认绑定 Female 图。

所有受光主体网格都写入 `HZZ_SUN`，仅有身体而没有 FACE 的模型不要求有效头骨，但必须绑定 Sun。旧版已应用材质可继续刷新旧控制并明确提示重新应用；重新应用后切换到新身体链路。新增调色组纳入归属、重复应用、回滚和恢复回收。
