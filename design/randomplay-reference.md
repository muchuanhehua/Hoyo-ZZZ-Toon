# RandomPlayToon 研究与接入方向

日期：2026-10-31。研究与三角色私有对照已完成，游戏外观未通过，运行源码未合并。

后续状态：用户确认采用此方向后，共用表面与资源接入已合并为 0.4.0，并完成新一轮运行验证与本地候选。本文保留最初研究批次的原始结论；当前状态见 [0.4 开发记录](DEVELOPMENT.md)。

## 固定参考与结论

用户指定 [RandomPlayToon](https://github.com/ImLaoBJie/RandomPlayToon)。本轮固定提交为 [`87ebc01de7c6a1ab4796b7da7196b88830d74667`](https://github.com/ImLaoBJie/RandomPlayToon/commit/87ebc01de7c6a1ab4796b7da7196b88830d74667)。用于运行控制的源码快照与 GPL 许可证在私有目录保存，文件 Git blob 摘要已核对。

它直接面向 Blender 5.2／EEVEE／PMX，适合参考材质分层、原始控制图接入和风格化高光。仓库自身将共用着色器定位为艺术化近似；展示还包含已校准材质、角色修正与风格预设。不能把其展示效果理解成任意 PMX 的统一默认结果。

本项目继续使用多角色共用实现与参数，不引入其角色指纹目录、材质槽号补丁、专属调色或完整风格预设。原始数据图的内容与 UV 对应继续单独核对。

## 对当前重构最有用的部分

| 模块 | 已读到的实现 | 本项目使用方向 |
|---|---|---|
| `materials/decoder.py` | 数据图独立 Non-Color，法线 RG 重建 Z，分开输出偏置、数值 ID、金属、高光和光滑度；数值 ID 不自动等同于皮肤／头发 | 独立纯解码接口，保持图像和用途语义分开 |
| `materials/graph.py` | 法线／光向明暗区间、亮暗色形成、有界场景遮挡、高光宽度与轮廓项 | 已作为未修改的共用核心控制运行；后续分离表面、光照和覆盖接口 |
| `materials/detail_review.py:hair` | 使用控制图 B 的图形高光、独立强度、暗部补偿和亮部柔化；辅助几何高光环默认关闭 | 已建立统一头发响应试验；不以横向白带补造未知高光 |
| `materials/scene_response.py` | 从真实 EEVEE 受光生成明暗区间，再单独处理颜色；避免把同一阴影能量反复相乘 | 尚未移植。后续须在 City-Terrace 核对亮度、阴影与颜色的职责，防止暗部发灰或双重压暗 |
| `specializations/surface_refinement.py:reflection` | 反射遮罩、粗糙度和底色保留分开，区分展示反光与实际 EEVEE 反射 | 尚未移植。借鉴能量与遮罩组织；不套用其中角色专属的强度、材质槽和发光修正 |
| `materials/source_asset_match.py` | 在实际材质三角面内部采样颜色，检查纹理变化、多个方向和次优候选；同颜色图还需比较伴随图 | 用于增强资源匹配研究。当前原生工程 UV 证据继续保留，不用文件名代替内容对应 |

参考中的脸部方向场和风格化鼻影与现有共享 SDF 是不同输入路径。本轮保留本项目已核对的 SDF，不把其脸部场直接替换为游戏 Lightmap，也不采用 `build_face` 中固定静止坐标作为通用参数。

## 本地实际对照

证据在 `.verification/randomplay-reference-20261031/`，入口为 `summary.json` 与 `three-character-comparison.png`。工具为 `tools/render_randomplay_control.py`。

艾莲、青衣、薇薇安各由冻结的 0.3 全身工程重新打开并渲染，使用相同 City-Terrace、机位、姿态与色彩管理。每个角色输出当前基线、上游共用表面核心、统一头发响应、关闭增强数据的四组图片，并保存私有工程。没有运行整个上游插件或加载其角色配置；这是共用核心的隔离对照，不等于复现其 README 示例。

三个案例分别有 7、5、5 个材质接入已有 UV 证据范围内的 M／A／N；其他项明确记录为没有控制图的通用路径。此处只使用共用数据语义，不按图集猜选原始材质 JSON，因此没有沿用上一轮 Body_2／Hair_T 的参数混用。透明覆盖、描边、眼层和 SDF 沿用输入工程。

共用皮肤色调仅按材质用途名称识别，其他设置按 `hair`／`skin`／通用表面管理；参数值与具体输入摘要记录在各案例 `report.json`。同一材质用途在三个案例中取相同参数，没有角色名或路径的风格分支。

实际观察：衣褶和袜面比冻结 0.3 更有连续体积，薇薇安腿部减少了过深的硬分区；但青衣头发仍偏绿，肤色、头发亮暗和反射均未达到游戏画面，局部皮肤阴影也过硬。头发图形高光试验的可见收益有限，不能据此称为发丝质感已修好。

三份运行报告均通过本次源数据与文件摘要保持检查。18 个运行 Python 文件与冻结 0.3 包逐一比较，差异为 0。仅修改私有工具、文档及研究输出，未安装、发布或构建新包；新核心的动画、完整恢复、多视角和游戏外观尚未验证通过。

## 已纠正的前轮错误

研究对照发现，本项目私有 `prototype_game_surface.py` 的解析式高光将 Blender `Geometry.Incoming` 取反。Blender 的这个向量指向观察者，可直接作为 `L + V` 的 V。代码现已纠正；冻结的 `authored-v4/` 仍保留错误方向的原始证据，不作为正确高光对照。旧解析式原型未在修正后单独重跑，本轮 RandomPlayToon 控制使用其正向视线实现。正式 0.3 的原生 Gloss 路径没有这处解析式代码。

依据：[Blender Geometry 输出说明](https://docs.blender.org/manual/en/3.5/render/shader_nodes/input/geometry.html)及[官方几何着色节点实现](https://github.com/blender/blender/blob/main/source/blender/gpu/shaders/material/gpu_shader_material_geometry.glsl)。此处核对的是方向约定，不据旧版手册宣称其他 5.2 行为。

## 后续实现顺序

1. 将控制图匹配与纯通道解码分离，输出明确的资产身份、UV、置信范围和未匹配原因。
2. 用一个共用表面接口组织亮暗、柔度、高光遮罩、光滑度和金属反射；皮肤、衣料、头发使用统一的用途默认值。
3. 独立管理头发的图形高光和亮部柔化，补核实际采样方向；在转灯、转头时检查形状与能量，避免用固定白带掩盖缺失输入。
4. 在同一背景下补齐有遮罩的反射与底色保留，再处理共用环境配色与轮廓光。先以三角色局部和全身对照判断有效性，再合并生命周期管理。

这一顺序继续服务基础渲染，单角色配置仍不在当前范围。
